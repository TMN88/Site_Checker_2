# Site Checker 2.0

Тестовая сборка **2.0.0-local.6**. Репозиторий: https://github.com/TMN88/Site_Checker_2. Полное ТЗ: [docs/Site_Checker_2_TZ.md](docs/Site_Checker_2_TZ.md).

В local.6 устранён отказ диагностики и списков соединений на OpenWrt с jq без Oniguruma. Используются переносимые операции jq без регулярных выражений. Причина подтверждена по журналам домашнего роутера; исправленные фильтры проверены на его настоящих ответах.

В local.5 активная вкладка выделена сплошным мягким розовым фоном. Кнопки проверки, отмены и настроек выстроены в одну строку; настройки справа. Диагностика показывает отдельные проверки с полученными значениями. Вместо проверки предполагаемого маршрута добавлены текущие сайты и соединения установленного обходчика. Определение установки и исправление чекбоксов local.4 сохранены.

Установщик **полностью удаляет первую версию без резервной копии**, если она найдена. Сначала проверяется установка версии 2, затем удаляются старые компоненты и конфигурация. Подробности: [Удаление версии 1](docs/REPLACING-V1.md).

## Что реализовано

- LuCI → Службы → Site Checker 2.0. Четыре вкладки: «Сайты», «Диагностика», «Сайты сейчас», «Соединения».
- Единая HTTP(S)-проверка по профилю Zapret Manager: параллельные curl, редиректы, Range 0–65535, User-Agent, таймаут и ограничение минимальной скорости.
- 16 исходных сервисов, чекбоксы, пользовательские домены, сохранение выбора на роутере. После сохранения настройки сворачиваются.
- До 32 сайтов, до 4 одновременных запросов; соединение 1–10 секунд, проверка сайта 1–15 секунд. По умолчанию 3 / 5 секунд и 4 запроса.
- Отдельные задания в /tmp: ручной запуск, запрет повторного запуска того же задания, чтение результата и отмена.
- Определение единственного Podkop, Forkop либо Forkozz. При нескольких источниках диагностика отказывается выбирать произвольный.
- Нативные адаптеры Podkop, Forkop 2.0 и Forkozz/NetShift из Zapret Manager. Только разрешённые диагностические команды, без restart/reload/apply.
- Состояние службы, версии, DNS, FakeIP и родные ошибки. Неполный JSON и неизвестные результаты не превращаются в «ВСЁ ОК».
- «Сайты сейчас» группирует текущие соединения sing-box по сайту и выходу. «Соединения» показывает устройства, назначения, порты, протоколы, секции и количество. Обновление только вручную, до 150 записей с отметкой об ограничении.
- Светлая и тёмная темы, неоновые акценты, мобильная компоновка.
- Самодостаточный установщик, проверка SHA-256, временный откат файлов версии 2 при сбое, сохранение её конфигурации при обновлении, отдельное удаление.
- Заготовка пакета для OpenWrt SDK и локальные проверки. Сборка пакетов SDK ещё не выполнялась.

## Готовые файлы

- outputs/site-checker2-2.0.0-local.6.sh — установочный файл со встроенными компонентами.
- outputs/site-checker2-2.0.0-local.6.sh.sha256 — SHA-256.
- outputs/Site_Checker_2_2.0.0-local.6.zip — исходный проект.
- outputs/ui-desktop-dark.png и ui-mobile-light.png — проверенный вид интерфейса с явно обозначенными тестовыми ответами.

Для установки на тестовый роутер:

~~~sh
wget -O /tmp/site-checker2-install.sh https://raw.githubusercontent.com/TMN88/Site_Checker_2/main/install.sh && sh /tmp/site-checker2-install.sh
~~~

Установщик допускает OpenWrt 24.10.x и 25.12.x, выбирает opkg/apk, при необходимости устанавливает curl, jq, setsid, rpcd, luci-base, ca-bundle. Он проверяет регистрацию RPC и восстанавливает свои файлы при ошибке. Работа на этих прошивках пока не подтверждена реальной установкой.

Удаление выполняется вручную:

~~~sh
sh /usr/libexec/site-checker2-uninstall --yes
~~~

Собственная конфигурация сохраняется в /etc/site-checker2/config.json. Настройки сетевых приложений не удаляются.

## Исправление HTTP 403 в local.1/local.2

Из-за umask 077 прежний установщик мог создать каталог интерфейса с правами 700, а файлы — с правами 600. Веб-серверу недоступен JavaScript страницы. В local.3 выставляются 755 для каталога интерфейса и 644 для публичных файлов, в том числе при обновлении. Настройки остаются 600 в каталоге 700, резервные копии также не открываются.

Обновись прежней командой wget выше. Для немедленного исправления уже установленного интерфейса можно выполнить только:

~~~sh
chmod 755 /www/luci-static/resources/view/site-checker2
chmod 644 /www/luci-static/resources/view/site-checker2/overview.js /www/luci-static/resources/view/site-checker2/style.css
~~~

Затем обнови страницу LuCI без кеша. Рекурсивно менять права всего /www или /etc не нужно.

## Диагностика и ограничения

Podkop: get_system_info, get_sing_box_status, check_dns_available, check_fakeip.

Forkop 2.0: get_system_info, check_service, check_dns, check_traffic, check_servers. Полная совместимость со старыми 0.x/1.x не заявляется; неподдерживаемые ответы дают неизвестный результат.

Forkozz: команды netshift get_system_info/get_sing_box_status/check_dns_available/check_fakeip и ucode netshift.uc diag. Отдельно установленный пакет NetShift не принимается за Forkozz.

Актуальная версия дополнительно запрашивается из официального GitHub Releases проекта с явным указанием источника. У Forkozz это версия движка NetShift; доступность обновления не означает, что оно уже одобрено текущей панелью. Нестандартные версии не сравниваются как обычные три числа.

FakeIP, отключённый из-за исключения самого роутера в Forkop, считается неприменимым. Если родные данные не позволяют установить корректность FakeIP, возвращается unknown. Это не диагноз неисправности.

Текущие соединения Forkozz берутся командой conns существующего /opt/zapret-manager-luci/netshift.uc — из того же модуля Zapret Manager, где раньше вызывался route. Forkop 2.0 использует собственный clash_api GET /connections. Для Podkop читается настроенный config_path и существующий контроллер sing-box. API автоматически не включается, настройки обходчика не меняются. При выключенном API или несовместимом ответе показывается ошибка, а не пустой успешный список.

Списки описывают соединения, которые видит sing-box. Весь прямой трафик локальной сети в них может отсутствовать. При отсутствии домена показан IP. Это снимок по нажатию, не история и не результат HTTP-проверки. Данные временно обрабатываются в закрытой папке /tmp/site-checker2; постоянное журналирование не добавлено. Ключ контроллера не передаётся в браузер, секретные и конфигурационные поля отбрасываются. Неизвестный выход не объявляется прямым.

GitHub Content проверяется по рабочему raw.githubusercontent.com URL из механизма Zapret Manager; подпись домена остаётся githubusercontent.com. HTTP 4xx/5xx и TLS-ошибки отображаются как неопределённые: они не доказывают блокировку. Проверка с роутера не равна доступу устройства в LAN.

При открытии страницы читаются только настройки и сохранённые результаты. Опрос запущенного пользователем задания получает его состояние и не запускает новые сетевые тесты. Постоянная служба и cron отсутствуют.

Настройки первой версии не переносятся и не резервируются. Если версия 2 уже настроена, её настройки сохраняются. Старые файлы и UCI-конфигурация версии 1 удаляются полностью после проверки версии 2.

## Проверки

~~~sh
node --test tests/*.test.cjs
node tools/ui-check.cjs
python tools/build.py
python tools/verify-build.py
~~~

Node.js/Python/браузер нужны только разработчику. На роутере они не устанавливаются.

На Windows тесты backend используют имеющийся jq и shell из среды разработки; отдельно адаптируют LF-вывод jq и отсутствие chmod. Команды обходчиков и RPC в тестах подменяются контролируемыми ответами. Изоляция групп процессов требует Linux и локально пропущена. Для Linux подготовлен GitHub Actions workflow; его актуальный результат виден во вкладке Actions.

Фактические результаты и оставшиеся проверки: [docs/VALIDATION.md](docs/VALIDATION.md).
