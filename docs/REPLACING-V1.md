# Замена Site Checker 1.0

По уточнению пользователя от 29.10.2026 версия 2 заменяет первую версию, если та найдена. Это уточнение отменяет требование параллельного сохранения установленной первой версии в исходном ТЗ. Исходный репозиторий Site_Checker не изменяется.

## Порядок установки

1. Проверить доступность зависимостей.
2. Сохранить известные файлы версии 1 и её конфигурацию в /root/site-checker2-backup-ДАТА-PID/legacy-v1. Копия сверяется по SHA-256.
3. Установить и проверить файлы, JSON-конфигурацию и RPC версии 2.
4. Только после успешной проверки убрать контроллер, страницу, три помощника, меню и конфигурацию первой версии.
5. Обновить кэши LuCI. Старая запись меню должна исчезнуть, остаётся Site Checker 2.0.

Резервная копия расположена в /root, а не /tmp, поэтому переживает перезагрузку. Установщик выводит точный путь. Каталоги общего назначения, Lua runtime, VPN, DNS, firewall и интеграция podkop-vpn-failover не удаляются. Старый install.sh --uninstall не вызывается.

## Настройки

Если второй версии ещё не было, доступный серверный список UCI sitecheck переносится в новую JSON-конфигурацию: известные сайты сопоставляются по имени/домену, сохраняется enabled, добавляются допустимые пользовательские домены.

Если настройки второй версии уже существуют, они сохраняются и имеют приоритет. Старый UCI-файл в любом случае остаётся в резервной копии.

Выбор второй таблицы версии 1 хранился в браузере и автоматически не переносится. Нестандартный или повреждённый список не импортируется; оригинал остаётся в резервной копии.

## Установка первой версии пакетом

Поддерживается известный пакет luci-app-sitecheck. До удаления проверяется его список файлов. Если пакет содержит посторонние пути, замена останавливается.

Для opkg сначала выполняется пробное удаление без принудительного разрыва зависимостей и без autoremove. Для apk сохраняются прямые зависимости новой версии luci-base/curl и проверяется пробный план удаления. Если план затрагивает другие пакеты, удаление не выполняется.

База пакетного менеджера вручную не переписывается. Если сам пакетный менеджер аварийно завершится после частичного удаления, установщик восстанавливает старые файлы, но может потребоваться проверка записи luci-app-sitecheck в пакетной базе. Исходный статус пакета сохранён в резервной копии.

## Возврат файлов первой версии

В резервной копии находится restore-helper.sh. Для известного точного пути резервной копии:

~~~sh
sh /root/site-checker2-backup-ДАТА-PID/legacy-v1/restore-helper.sh restore /root/site-checker2-backup-ДАТА-PID/legacy-v1
~~~

Это возвращает только файлы первой версии; пакетную запись при пакетной установке нужно проверять отдельно. Версия 2 при таком ручном возврате не удаляется автоматически.

## Проверки

Адресные тесты воспроизводят копирование и удаление только разрешённых файлов, отсутствие версии 1, изменение файла во время установки, восстановление, перенос UCI, пакетные сценарии apk/opkg и отказ удаления посторонних файлов/зависимостей.

Дополнительно Linux-тесты запускают настоящий установочный скрипт с настоящим встроенным архивом в изолированной тестовой папке: успешная замена, отказ регистрации RPC и сохранение существующих настроек версии 2. Это проверки на моделях, не испытания реального OpenWrt.
