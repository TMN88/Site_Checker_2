# Проверки Site Checker 2.0

## Актуальная сборка local.6

На домашнем роутере пользователя (OpenWrt 25.12.5, jq 1.8.1 без Oniguruma, Forkozz/NetShift 0.9.12) прочитаны журналы. Все три сбоя вызваны regex-функциями jq, нативные ответы содержат корректные данные. Кандидатные переносимые фильтры проверены на устройстве во временной папке: диагностика вернула ok, семь строк и ноль проблем; список обработал 50 текущих соединений. Ни jq, ни обходчик не заменялись. Добавлен тест отличия ошибки обработчика от отмены и запрет regex-зависимости в проверку сборки. Результаты полного повторного запуска после установки фиксируются отдельно в журнале и publication.json.

## Предыдущая сборка local.5

Добавлены семь адресных тестов: подробные значения диагностики, оба представления Forkozz conns, нативный транспорт Forkop, Podkop с защищённым заголовком, ошибки/неполные ответы API, запрет автоматического включения API и ограничение больших списков. Браузер проверяет розовую активную вкладку, три кнопки на одной линии с настройками справа, сохранение выбора, развёрнутую диагностику, группировку сайтов/соединений, IPv6 и мобильную ширину. Проверки используют изолированные ответы и не доказывают работу на роутере.

## Локальный результат

- 36 тестов backend/probe: **35 прошли, 1 пропущен**. Пропущена проверка Linux-групп процессов: текущая среда Windows.
- Проверены JSON-схема настроек, сохранение и ограничение количества сайтов, недопустимые типы и домены, дубликаты и JSON-потоки.
- Проверены реальный shell-модуль curl с подменённым транспортом, HTTP/DNS/TLS/таймауты, безопасные аргументы и отсутствие отражения секретных полей.
- Пул действительно ограничивает параллелизм, пропускает отключённые сайты и сохраняет порядок результатов.
- Проверены асинхронный запуск, отказ повторного запуска и чтение результата.
- Нативные ответы Podkop, Forkop и Forkozz подменены фиксированными JSON-ответами по изученным схемам. Проверены выбор единственного приложения, отказ при конфликте, неверные/неполные ответы, версии, исключённый роутер/FakeIP и ошибки серверов.
- Проверены домены, IPv4 и IPv6; ошибки адресов и ввод команд отклоняются.
- Проверено подключение настоящих имён diag/route к установленному модулю Forkozz. Сам движок в тестах подменён: это проверка интеграционного кода, а не настоящих сетевых правил.
- Отдельный браузерный прогон реального LuCI-view с подменённым RPC прошёл: загрузка без автопроверок, вкладки, запуск сайтов, сохранение выбора, быстрые домены, диагностика, маршрут, отмена и отсутствие горизонтальной прокрутки на ширине 390 px.
- Просмотрены снимки тёмной настольной и светлой мобильной компоновки. Снимки прямо подписаны как тестовые данные.
- Проверен самодостаточный установщик: SHA-256 встроенного архива, соответствие всех 14 файлов исходникам, безопасные пути, права исполняемых файлов и синтаксис shell.

## Публикация и внешние проверки

- Репозиторий Site_Checker_2 создан публичным по разрешению пользователя. Подготовленный код публикуется в main.
- Workflow запускается при публикации. Локальные результаты выше не заменяют результат CI.
- Архивы исходных проектов скачаны только для анализа. Их рабочие файлы не изменялись.
- Пакет в OpenWrt SDK не собирался; Makefile — подготовленный исходник для дальнейшей проверки.
- opkg/apk, rpcd и полноценная LuCI на настоящем OpenWrt не проверены.
- Проверка групп процессов/отмены нативных дочерних команд на Linux ещё нужна.
- Ни одна диагностическая команда не выполнялась на реальном обходчике.

## Что нужно проверить на тестовом роутере

После отдельного согласования изменений устройства:

1. Резервная копия своих файлов и независимый доступ к роутеру.
2. Установка на 24.10.x/opkg и 25.12.x/apk; регистрация site-checker2 в ubus и меню LuCI.
3. Проверка сайтов с обычной сетью, отказом DNS, ошибкой TLS и таймаутом.
4. Отмена активной проверки; отсутствие оставшихся процессов и повторный запуск.
5. Каждый обходчик отдельно: родные команды, версии, DNS и применимость FakeIP.
6. Для Forkozz — актуальный netshift.uc, нестандартный FakeIP-пул, доменные и IP-правила, исключения, source-dependent правила и неработающая служба.
7. Светлая/тёмная темы LuCI, Argon/Footstrap/Aurora и телефон.
8. Обновление с сохранением настроек, откат при ошибке и удаление только своего приложения.

## Известные ограничения

- Раздел анализа маршрута убран по требованию пользователя в local.5; следующие прежние ограничения его внутреннего обработчика сохранены как история.
- Для Forkozz используется уже установленный анализатор Zapret Manager, а не отдельная копия его кода. Если модуль отсутствует, выводится ограничение.
- Без подтверждённого перехвата через известный FakeIP-диапазон или nft-наборы совпадение VPN-правила возвращает неопределённый предполагаемый выход. Нестандартные диапазоны могут требовать доработки.
- Адрес клиентского устройства пока не вводится. Для правила, требующего source, выводится соответствующая причина неопределённости.
- IPv6 принимается и проверяется, но в изученном нативном анализаторе cidr_hit учитывает только IPv4. Поэтому результат IPv6 показывается с неопределённым выходом и явной причиной, без ложного вывода «напрямую».
- Последняя версия Forkozz берётся из релизов движка NetShift; она может ещё не быть разрешена панелью.
- Выбор второй таблицы Site Checker 1.0 хранился в браузере и автоматически не переносится.
- Временные результаты доступны всем пользователям LuCI с правом чтения этого приложения. Полные конфиги/ключи в результат не возвращаются.
- Права на запуск, сохранение и отмену защищены отдельными write ACL. Совместимость исполнения этих ACL нужно подтвердить на роутере.
